# 运行时与动效处理

仅在静态保存无法充分解释页面或交互时读取。

## 先区分资源失败与实现缺口

记录实际控制台错误、失败请求、缺失模块或不工作的交互。先检查本地 URL、MIME 类型、字体、脚本顺序和初始化条件，避免“看不见”就重写动画。

| 观察到的情况 | 处理方向 |
| --- | --- |
| Webflow 动画不起作用 | 检查 `data-wf-page` / `data-w-id`、schunk、页面入口、GSAP 插件与加载顺序；保留原始 ID。 |
| ES module 或动态 chunk 失败 | 检查 import 相对路径、importmap、publicPath、CORS/MIME；对明确观察到的模块建立本地依赖图。不要盲改所有 JS 字符串。 |
| SSR 页面正常但 hydration 报错 | 确认框架初始数据、路由与 asset prefix；仅保存渲染后的 DOM 常常不够。把具体修复可行性与用户约定的保留源码策略对齐。 |
| 动态数据影响页面外观 | 记录实际公开响应及状态；允许范围内可用本地快照适配。不要冒充有实时业务能力。 |
| canvas、Lottie、WebGL 或 3D | 找到公开资源、运行时和相机/时间线配置；截图不能替代运行效果。资源不可得时问用户是否接受替代方案。 |
| 受限资源、到期 URL、登录内容 | 说明具体受影响元素；请用户提供可用资源或授权访问路径。不要推测内容，也不自行绕过访问限制。 |

保留源码与手写重建属于不同的交付路线。若原始运行时无法可靠本地运行，向用户说明：已经保存哪些部分、缺什么、为什么影响外观/动画，以及可选的下一步。得到用户选择后继续依赖该决定的工作，不先做好近似版本再当作默认交付。

## 动效观察记录

对本次页面实际存在的效果记录触发条件与状态，而不是机械要求每种效果都存在：

- 加载：初始隐藏状态、元素进场顺序、遮罩/文字拆分、字体加载后是否重排。
- 滚动：起止点、pin 持续距离、scrub、进入/离开行为及反向滚动；快速跳转后是否恢复正确状态。
- 菜单：打开/关闭、遮罩、背景模糊、滚动锁定、路由跳转；原站支持键盘时也要保留。
- hover / pointer：光标、磁吸、双层文字、箭头、图片缩放；离开后复位。
- 循环/轮播：方向、速度、无缝边界、active 状态、手动切换与自动播放关系。
- 视频：封面、裁切、muted / playsinline / loop、播放/暂停及浏览器自动播放限制。

Lenis、GSAP ticker 和 ScrollTrigger 的更新要符合原站，避免同时存在两套 requestAnimationFrame 循环。对 resize、字体加载及内容改变后的布局刷新进行实际检查。不要把系统减少动态效果设置造成的暂停误判为程序失效。

只有当支持的浏览器工具确实允许时，才使用其截图、只读 DOM/样式观察、日志和视口功能；不能假定存在 Playwright CDP、任意 evaluate 写入或窗口尺寸 API。无法调整视口时，可用自己编写的临时本地 iframe 检查静态布局，但应标明这只是 iframe 的响应式检查，不等同于触屏设备或顶层滚动行为验收。

## 需要用户选择的情况

当关键效果依赖未公开源文件、原站接口、无法下载的主视觉素材，或完整运行必须换技术栈时，用具体页面/效果描述差异。不要泛泛声称“某框架不能复刻”。保留已完成成果与问题清单，并继续处理已经授权且不依赖选择的部分。
