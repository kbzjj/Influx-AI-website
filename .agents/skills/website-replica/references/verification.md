# 对照验收与交付

## 证据与完成标准

为本次 scope 制作验证记录，覆盖已确认页面及关键状态。具体数量由页面和交互决定，不按固定截图数验收。

| 检查 | 证据 | 不能推出的结论 |
| --- | --- | --- |
| 文件和链接完整 | manifest、`audit.py` 输出、HTTP 200 / 媒体 206 等成功响应 | 页面已忠实还原 |
| 字体与媒体正确 | 实际字体、字重，图片自然尺寸，视频 readyState / 播放状态 | 所有懒加载资源都已加载 |
| 布局一致 | 相同视口的区块宽高、关键边界、计算样式 | 所有像素和动效都一致 |
| 视觉一致 | 同视口、缩放、滚动位置与状态的原站/本地截图 | 动态帧或所有屏幕都一致 |
| 动效可用 | 触发前、过程中、完成/反向状态和实际交互结果 | 所有交互仅凭一个状态就完成 |
| 运行时正常 | 实际浏览器错误/请求、主要操作结果 | 仅静态解析就能验证动态模块 |

先对齐浏览器视口、页面缩放、字体加载、滚动条与滚动状态。将视频随机帧、跑马灯相位、动画播放时刻和字体抗锯齿产生的差异独立说明；截图差分图只能辅助定位，不能把随机运动误判成布局错误，也不能用几何一致代替完整视觉验收。

覆盖整页，不能只验首屏：实际滚动使懒加载和动画触发，检查底部内容和导航往返。响应式至少核对用户指定的视口；未指定时选择一个桌面和一个手机宽度并记录实际值，不在控制 API 不支持时伪造尺寸。

操作本地菜单、轮播、Tabs、FAQ 和视频等实际存在的控件，检查切换后的内容/状态，而非仅记录“点击成功”。表单使用虚构测试值并确认只有本地反馈。对于外链、远程播放器或 API，明确保留策略和联网需求。

发现关键缺口就修复该边界，针对变化复测；不进行无关的无限检查。浏览器不可用、资源不完整或等待用户决策时，记录未验证/受限项，不能报告“1:1 验收完成”。

## 建议输出

```text
<skill-dir>/assets/templates/<site-slug>/
  index.html
  pages/...                 如果有确认的子页面
  assets/...
  _source/...               原始文本快照，可选
  scope.json                用户确认范围的工作记录
  asset-manifest.json
  template.json             模板中心注册元数据
  local-preview.js          按实际需要
  README.md                 启动、页面入口、限制
  STUDY_GUIDE.md             本次真实源码和动效学习索引
  qa/
    static-audit.json
    verification.md
    reference-*.png
    local-*.png
```

预览从输出目录启动到可用 loopback 端口，先确认 HTTP 成功，再在可用的应用浏览器里打开。本地预览是交付的一部分，应让服务继续运行，并告诉用户如何停止。已有服务可以复用时先确认它确实服务于所需目录；不停止其他项目服务，也不覆盖项目根入口。可按用户操作系统提供双击启动脚本；没有需要时不引入 npm 构建系统。

统一从 [模板中心](template-library.md) 打开最终模板，并验证封面跳转、根路径路由、分类/搜索及学习文档。原模板仍是完整独立页面；中心不通过远程站点 iframe 冒充本地复刻。

`scope.json` 建议字段：`source_url`、`confirmed_scope`、`included_pages`、`excluded`、`key_interactions`、`viewports`。这是会话确认的记录，不是可以由程序随意写一个布尔值替代的用户授权。

`verification.md` 应用短表列出页面/状态、实际检查、证据路径、结果与剩余差异。截图从浏览器工具保存，不能拿重新生成的示意图冒充截图。不要把几何数据、网络检查或交互验证写成已完成，除非本次确实执行过。

学习文档应链接当前源码，指出字体与设计变量、主要区块选择器、动画入口、触发器、时间线/参数、资源映射及本地适配边界。若另存格式化学习副本，明确它不参与页面运行，避免重复初始化动画。

最终用简洁中文交付：本地 URL、源码和学习文档路径、复刻范围、已验证项目，以及影响还原的限制。用户关心查看和学习结果，不需要重述全部下载日志。
